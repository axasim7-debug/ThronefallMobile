# السيرفر (Thronefall.Server)

السيرفر الـ**Authoritative** للعبة (راجع `docs/GAME_DESIGN.md` §5.3) — مصدر الحقيقة الوحيد لحالة أي مباراة. العميل (`client/`) شاشة عرض وتواصل بس، مفيش منطق لعبة عليه.

## البنية

| المشروع | الغرض |
|---|---|
| `Thronefall.PositionalEngine` | **المحرك الشغال فعلياً حالياً (شحن)** — نقل C# أمين لـ`tools/battle-sim/src/{engine,match,match-content,match-strategies}.js`: نموذج قتال **مستمر ومرتبط بالموضع الفعلي** (مواضع (x,z) حقيقية لكل وحدة ومبنى، ضرر مستمر بمرور الوقت، لا حل فوري، لا نظام أنواع وحدات متضاربة). `Thronefall.Api` بيوصل على المحرك ده حالياً — البروتوكول بقى بيبعت مواضع حقيقية وبيقبل أمر `moveUnit` (تحريك وحدة، أساس ميكانيكية السحب/التراجع المستقبلية). |
| `Thronefall.PositionalEngine.Tests` | اختبارات xUnit — نفس ثوابت `tools/battle-sim/test/{battle,match}.test.js` **+ اختبارات مضاهاة (cross-validation)** ضد أرقام محققة فعلياً من محرك JS **+ اختبارات بروتوكول real-time عدائية** (`PlayerCommandTests.cs` — عميل بيكذب، أوامر غير شرعية، تماثل بين لاعبين). |
| `Thronefall.Engine` | **المحرك القديم — لسه موجود في الريبو لكن مش موصول بحاجة**. نموذج قتال مرحلي/فوري (برج←مزرعة←قلعة — مفيش سور، اتحذف). كان هو الشغال قبل التحويل الكامل للنموذج الجديد. راجع `docs/PROGRESS.md` لتاريخ القرار الكامل. |
| `Thronefall.Engine.Tests` | اختبارات المحرك القديم — لسه بتعدي (37/37) رغم إنه مش موصول، عشان الكود يفضل سليم لو احتجناه للرجوع. |
| `Thronefall.Api` | ASP.NET Core — **`/ws/match`: بروتوكول أوامر اللاعب real-time** (مباراة حية، tick بالثانية، أوامر لاعب فعلية، مواضع حقيقية). و`/ws/demo-match` بوت-ضد-بوت متسابة كاختبار اتصال سريع. بيستخدم `Thronefall.PositionalEngine`. |

### الملفات المهمة

- `Thronefall.PositionalEngine/MatchSession.cs` — **حلقة التكات الوحيدة في المشروع**. المباراة الحية والمحاكاة الدفعية (`Match.SimulateMatch`) الاتنين بيمروا منها، فالأرقام المُتحقَّق منها بتفضل بتوصف نفس اللعبة اللي بتتلعب فعلاً.
- `Thronefall.PositionalEngine/PlayerCommands.cs` — أنواع الأوامر (بما فيها `MoveUnit`)، التحقق، والمتحكّمات (بوت / لاعب حقيقي).
- `Thronefall.PositionalEngine/MatchSnapshot.cs` — شكل الحالة اللي بيتبعت للعميل، بمواضع حقيقية لكل وحدة/مبنى.
- `Thronefall.Api/LiveMatch.cs` — البروتوكول على السلك (WebSocket).

## ليه محرك منفصل عن JS بدل ما نستخدم نفس الكود؟

`tools/balance-sim` و`tools/battle-sim` (JS/Node) هما أدوات التكرار السريع لضبط الأرقام — سهلة التعديل والاختبار الفوري. لكن **السيرفر الفعلي اللي المباريات الحقيقية هتشتغل عليه لازم يكون .NET** (قرار معماري من `docs/GAME_DESIGN.md`). فبنحافظ على كل زوج (JS ↔ C#) **متزامن عمداً**: أي رقم يتضبط ويتأكد في JS، يتنقل هنا بعدها بنفس القيمة بالظبط — والاختبارات المضاهاة (`CrossValidate_*`) هي اللي بتضمن التزامن ده، مش مجرد نية طيبة.

## ليه محرك جديد بجانب القديم، مش تعديل الموجود؟ ولماذا اتبدّل بالكامل بعد كده؟

نموذج القتال الجديد (`Thronefall.PositionalEngine`) كان تغيير جذري في الشكل — مواضع حقيقية وضرر مستمر بدل حل فوري مرحلي — مش تعديل أرقام على نفس الهيكل. القرار الأول (من المستخدم): نبني المحرك الجديد كمشروع منفصل تماماً، نختبره ونثبّته لوحده، من غير ما نلمس `Thronefall.Engine` الشغال فعلياً. بعد ما المحرك الجديد بقى مُختبر بالكامل (18 اختبار، بعدين 36 مع بروتوكول الأوامر الحية)، القرار التاني: **نبدّل `Thronefall.Api` بالكامل للمحرك الجديد**، لأن `Thronefall.Engine` أصلاً كان تجربة أولية قبل ما نوصل للتصميم الصح، ومفيش داعي نعقّد السيرفر بمسارين. `Thronefall.Engine` اتسيب في الريبو من غير حذف (كود شغال ومُختبر، ممكن يفيد كمرجع)، لكن `Thronefall.Api` مبيستخدمهوش خالص دلوقتي.

## التشغيل

```bash
# محتاج .NET 8 SDK (dotnet --version)
cd server
dotnet test Thronefall.PositionalEngine.Tests/Thronefall.PositionalEngine.Tests.csproj  # اختبارات المحرك الشغال فعلياً
dotnet run --project Thronefall.Api/Thronefall.Api.csproj                                # يشغّل السيرفر على http://localhost:5246
```

العب مباراة حقيقية (بعد ما تشغّل السيرفر) — العميل المرجعي مش محتاج أي تثبيت:

```bash
curl http://localhost:5246/health

# مباراة كاملة بأوامر لاعب حقيقية (بناء، تدريب، وتحريك وحدات فعلي)
node tools/live-client/play.js --url ws://127.0.0.1:5246 --opponent atk --speed 60

# نفس الحاجة + أوامر غير شرعية عمداً لإثبات إن السيرفر بيرفضها
node tools/live-client/play.js --url ws://127.0.0.1:5246 --probe
```

## بروتوكول `/ws/match`

**من العميل** — نية واحدة لكل رسالة:

```json
{"type":"command","kind":"build|train|repair|moveUnit","arg":"farm","seq":1}
{"type":"command","kind":"moveUnit","arg":"u17","x":1.5,"z":-2.5,"seq":2}
```

`x`/`z` مهمين بس لـ`moveUnit` (`arg` فيها = معرّف الوحدة، مش نوع مبنى/جندي).

**من السيرفر**:

| الرسالة | متى | المحتوى |
|---|---|---|
| `matchStarted` | مرة واحدة | جهتك، الخصم، مدة الجولة، و**كتالوج التكاليف والأرقام** (تكلفة/HP/DPS/مدى/سرعة كل جندي، عشان العميل يرسم أزراره ويحسب أحجام الوحدات) |
| `ack` | لكل أمر | `accepted` + `reason` نصّي ثابت عند الرفض + `seq` المُرسَل |
| `state` | كل tick | لقطة كاملة: ذهب/دخل/بناء لكل جهة، **مواضع (x,z) حقيقية لكل مبنى ووحدة حية**، وجهة كل وحدة (`waypointX`/`waypointZ`) لو بتتحرك |
| `matchEnded` | مرة واحدة | الفائز وسبب الحسم |

**قواعد ثابتة في البروتوكول**:
- **السيرفر هو السلطة**: كل أمر بيمر على نفس دوال المحرك اللي البوتات بتمر عليها. عميل متلاعب فيه أقصى ما يقدر عليه إن أمره يترفض.
- **الأوامر بتتطبّق عند حدود الـtick**، فمفيش أفضلية لمن يرسل أسرع داخل نفس الثانية.
- **الجندي المُدرَّب مبيتحركش لوحده أبداً** — بيفضل واقف مكانه لحد ما اللاعب يبعت `moveUnit` صراحةً (تحكّم يدوي كامل، ده أساس رؤية السحب-والإفلات الحية).
- **القيم الفارغة بتتكتب صراحةً** (`null` مش حذف الحقل) عشان شكل الحالة يفضل ثابت للعميل.

## لسه مش موجود (الخطوة الجاية)

- **ربط `client/` بالبروتوكول الجديد** — البروتوكول جاهز ومُختبر (`tools/live-client/play.js` هو المرجع الكامل)، لكن `client/` (الواجهة الفعلية) لسه بتتكلم بشكل السلك القديم بالكامل ومحتاجة إعادة تصميم — سحب-وإفلات حقيقي بدل الأزرار، ورسم الوحدات بمواضعها الحقيقية بدل عدّاد مجرّد.
- **PvP حقيقي**: الخصم حالياً بوت. `MatchSession` بياخد أي متحكّمين، فتوصيل `PlayerController` اتنين هو كل الناقص من ناحية المحرك — الباقي matchmaking.
- **قادة ومهارات الغضب**: النموذج الجديد لسه مفيهوش نظام القادة/الغضب من المحرك القديم — قرار تصميمي لاحق (هل يترجع بشكل مختلف يناسب القتال المستمر، ولا حاجة تانية خالص).
- الحسابات، تسجيل الدخول، تخزين تقدّم اللاعب (بطاقات، ليفلات، معدات).
- Matchmaking بالكؤوس (`docs/GAME_DESIGN.md` §موديل الربح والمنافسة).
- إعادة الاتصال بعد انقطاع الشبكة (الجلسة حالياً بتنتهي مع السوكت).
