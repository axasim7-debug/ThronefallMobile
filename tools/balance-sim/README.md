# محاكي التوازن (Balance Simulator)

أداة اختبار قابلة لإعادة الاستخدام — الهدف منها: أي إضافة مستقبلية (بطل جديد، جندي جديد، مبنى جديد، تعديل رقم موجود) **لازم تمر من هنا قبل ما تُعتمد**، عشان نتأكد إنها مش هتكسر التوازن أو "تقتل" اللعبة (مباراة تنتهي فورياً، أو استراتيجية واحدة تسحق الباقي دايماً).

> القاعدة الأساسية اللي بنيت عليها الأداة دي: **الاختبار جزء من العمل، مش خطوة بعده** (راجع `docs/PROGRESS.md`).

## الاستخدام السريع

```bash
cd tools/balance-sim
npm test          # يشغّل كل اختبارات التوازن (pass/fail تلقائي)
npm run sim       # يطبع نتيجة كل مواجهة بالتفصيل للمراجعة اليدوية
```

## بنية المشروع

| الملف | الغرض |
|---|---|
| `src/content.js` | **كل بيانات "البطاقات"** — الاقتصاد، المباني، الدفاع، الجنود. هنا فقط تضيف محتوى جديد. |
| `src/engine.js` | محرك المحاكاة العام (اقتصاد + قتال طبقي: سور ← برج ← قلعة). **متضربش فيه غالباً.** |
| `src/strategies.js` | أنماط بناء ثابتة (eco/def/atk) تُستخدم كخصوم اختبار قياسيين. |
| `test/balance.test.js` | مجموعة اختبارات آلية (`node --test`) — سلامة المنطق + قواعد التوازن. |
| `scripts/run-matchups.js` | أداة طباعة نتائج كل المواجهات للمراجعة بالعين. |

## إزاي تضيف محتوى جديد (بطل/جندي/مبنى) وتختبره

1. **أضف البيانات في `src/content.js` فقط** — مثلاً جندي جديد:
   ```js
   TROOPS.t2 = { name: "T2 — رامي سهام", cost: 90, buildTime: 5, hpFactor: 1.5, dpsFactor: 0.9, marchTime: 4 };
   ```
   ماتلمسش `engine.js` — لو محتجت تلمسه، ده معناه إن نوع المحتوى الجديد يحتاج آلية مختلفة جوهرياً (مثلاً قدرة خاصة)، وده قرار تصميمي لازم يتناقش الأول.

2. **لو عايز تختبر استراتيجية جديدة تستخدم المحتوى الجديد**، ضيفها في `src/strategies.js` بنفس نمط `ECO`/`DEF`/`ATK` (خاصية `decide(player, content)`)، وضيفها لمصفوفة `MATCHUPS` في `test/balance.test.js`.

3. **شغّل `npm run sim`** وشوف النتائج بعينك الأول — هل فيه حاجة غريبة (رقم صفر، مباراة انتهت في ثوانٍ، جيش بقيمة آلاف)؟

4. **شغّل `npm test`** — لازم كل الاختبارات تعدي (ما عدا الاختبارات المعلّمة `todo` وهي قضايا مفتوحة موثقة). لو اختبار فشل، ده معناه المحتوى الجديد كسر قاعدة توازن أساسية — راجع رسالة الخطأ، هتقولك بالظبط إيه اللي حصل.

5. **كرر الاختبار من أكتر من زاوية قبل ما تعتمد أي رقم نهائي**: جرب المحتوى الجديد في كل المواجهات الممكنة، وجرب حالات متطرفة (رقم = صفر، رقم كبير جداً) — مش بس السيناريو "الطبيعي". هذا مش اختياري، ده الاتفاق الأساسي للعمل على اللعبة دي.

## إيه اللي الاختبارات بتتأكد منه بالظبط

- **سلامة المنطق**: كل استراتيجية توصل لثكنتها وتنتج جنود فعلاً (يمسك أخطاء زي "الذكاء الاصطناعي علق في حلقة" اللي حصلت فعلياً أثناء بناء الأداة دي).
- **عدم وجود قيم فاسدة**: ذهب سالب، HP سالب، NaN.
- **الوتيرة (Pacing)**: مفيش مباراة تنتهي قبل 60 ثانية (انهيار فوري)، ومباريات المرآة (نفس الاستراتيجية ضد نفسها) لازم تقع بين 120-360 ثانية (نطاق الجولة المستهدف).
- **الهيمنة**: مفيش استراتيجية واحدة تكسح كل المواجهات (اختبار موجود لكنه `todo` حالياً — قضية مفتوحة، شوف تحت).

## القضايا المفتوحة (لازم تُقرأ قبل أي تعديل جديد)

**استراتيجية "اقتصاد أولاً" (eco) بتكسب كل مواجهة غير متماثلة.** جُرّبت 4 محاولات إصلاح: تكلفة/عائد المزرعة (مرتين)، سقف صارم لمزرعة واحدة، **وتنفيذ فعلي لآلية "الدفاع يتعزز مع الوقت"** (`content.DEFENSE.reinforce` — الأبراج/القلعة تبدأ بنسبة من قوتها الكاملة وتتحصّن تدريجياً). النتيجة بعد اختبار الآلية الأخيرة بـ3 إعدادات مختلفة: **بتغيّر توقيت نهاية المباراة، مش مين بيكسب**.

**التشخيص**: الفوز محكوم بسباق الإنتاج الكلي على طول المباراة، مش بقوة الدفاع في لحظة معينة — و"eco" عندها دخل مضاعف **دائم** لباقي الجولة، فأي فرق دخل دائم هيتراكم ويكسب بغض النظر عن توقيت قوة الدفاع. هل ده عيب أصلاً؟ في ألعاب مشابهة (Clash Royale)، هجوم ما بيخلصش اللعبة بيخسر عادة قدام إدارة موارد صبورة — والاختبار بيّن إن الهجوم المبكر بيسبب ضرر حقيقي (يوصل بقوة eco لـ44-66% بس مش 100%)، مش عديم الفائدة. **قرار مستخدم مطلوب** قبل أي محاولة تانية — راجع `docs/PROGRESS.md`.

## الأرقام المعتمدة حالياً (Snapshot)

راجع `src/content.js` للأرقام الفعلية دايماً (هو مصدر الحقيقة، مش هذا الملف) — لكن كملخص: مدة الجولة 360 ثانية، دفاع أساسي = برجين (700 HP لكل واحد) + قلعة (1200 HP)، جولات اختبار وصلت لمدى 162-352 ثانية حسب الاستراتيجيتين (راجع `docs/PROGRESS.md` لتفاصيل رحلة الاختبار الكاملة).
