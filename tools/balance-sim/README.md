# محاكي التوازن (Balance Simulator)

أداة اختبار قابلة لإعادة الاستخدام — الهدف منها: أي إضافة مستقبلية (بطل جديد، جندي جديد، مبنى جديد، تعديل رقم موجود) **لازم تمر من هنا قبل ما تُعتمد**، عشان نتأكد إنها مش هتكسر التوازن أو "تقتل" اللعبة (مباراة تنتهي فورياً، أو استراتيجية واحدة تسحق الباقي دايماً).

> القاعدة الأساسية اللي بنيت عليها الأداة دي: **الاختبار جزء من العمل، مش خطوة بعده** (راجع `docs/PROGRESS.md`).

## الاستخدام السريع

```bash
cd tools/balance-sim
npm test          # يشغّل كل اختبارات التوازن (pass/fail تلقائي)
npm run sim       # يطبع نتيجة كل مواجهة بالتفصيل للمراجعة اليدوية
```

## بنية المشروع

| الملف | الغرض |
|---|---|
| `src/content.js` | **كل بيانات "البطاقات"** — الاقتصاد، المباني، الدفاع، الجنود. هنا فقط تضيف محتوى جديد. |
| `src/engine.js` | محرك المحاكاة العام (اقتصاد + قتال طبقي: سور ← برج ← مزرعة ← قلعة). مُعمَّم الآن ليدعم 3 خصائص بيانات لأي جندي بدون تعديل المحرك: `bypasses` (تخطي مراحل، زي تسلق النينجا للسور)، `damageProfile` (مضاعف ضرر حسب نوع الهدف، زي حرق المزارع أو هدم الأسوار)، `defenseResistFactor` (مقاومة رد الفعل، زي مسافة الرماة). **لو محتاج تتخطى الخصائص دي (قتال جندي-ضد-جندي، ضرر متراكم بالوقت، قدرة تؤثر على جنود تانية) — ده قرار يستاهل نقاش، مش تعديل عادي.** |
| `src/strategies.js` | أنماط بناء ثابتة (eco/def/atk) تُستخدم كخصوم اختبار قياسيين، وتشكيلة القادة (`squad`) اللي بتدخل بيها المباراة. |
| `test/balance.test.js` | مجموعة اختبارات آلية (`node --test`) — سلامة المنطق + قواعد التوازن. |
| `scripts/run-matchups.js` | أداة طباعة نتائج كل المواجهات للمراجعة بالعين. |

## إزاي تضيف محتوى جديد (بطل/جندي/مبنى) وتختبره

1. **أضف البيانات في `src/content.js` فقط** — مثلاً جندي جديد:
   ```js
   TROOPS.t2 = { name: "T2 — رامي سهام", cost: 90, buildTime: 5, hpFactor: 1.5, dpsFactor: 0.9, marchTime: 4 };
   ```
   ماتلمسش `engine.js` — لو محتجت تلمسه، ده معناه إن نوع المحتوى الجديد يحتاج آلية مختلفة جوهرياً (مثلاً قدرة خاصة)، وده قرار تصميمي لازم يتناقش الأول.

2. **لو عايز تختبر استراتيجية جديدة تستخدم المحتوى الجديد**، ضيفها في `src/strategies.js` بنفس نمط `ECO`/`DEF`/`ATK` (خاصية `decide(player, content)`)، وضيفها لمصفوفة `MATCHUPS` في `test/balance.test.js`.

3. **شغّل `npm run sim`** وشوف النتائج بعينك الأول — هل فيه حاجة غريبة (رقم صفر، مباراة انتهت في ثوانٍ، جيش بقيمة آلاف)؟

4. **شغّل `npm test`** — لازم كل الاختبارات تعدي (ما عدا الاختبارات المعلّمة `todo` وهي قضايا مفتوحة موثقة). لو اختبار فشل، ده معناه المحتوى الجديد كسر قاعدة توازن أساسية — راجع رسالة الخطأ، هتقولك بالظبط إيه اللي حصل.

5. **كرر الاختبار من أكتر من زاوية قبل ما تعتمد أي رقم نهائي**: جرب المحتوى الجديد في كل المواجهات الممكنة، وجرب حالات متطرفة (رقم = صفر، رقم كبير جداً) — مش بس السيناريو "الطبيعي". هذا مش اختياري، ده الاتفاق الأساسي للعمل على اللعبة دي.

## إيه اللي الاختبارات بتتأكد منه بالظبط

- **سلامة المنطق**: كل استراتيجية توصل لثكنتها وتنتج جنود فعلاً (يمسك أخطاء زي "الذكاء الاصطناعي علق في حلقة" اللي حصلت فعلياً أثناء بناء الأداة دي).
- **عدم وجود قيم فاسدة**: ذهب سالب، HP سالب، NaN.
- **الوتيرة (Pacing)**: مفيش مباراة تنتهي قبل 60 ثانية (انهيار فوري)، ومباريات المرآة (نفس الاستراتيجية ضد نفسها) لازم تقع بين 120-360 ثانية (نطاق الجولة المستهدف).
- **الهيمنة**: مفيش استراتيجية واحدة تكسح كل المواجهات — اختبار حقيقي (مش `todo`) بقى شغال ✅.
- **كل جندي/بطاقة لوحدها**: أي جندي جديد تضيفه في `TROOPS` بيتفحص تلقائياً (مركّب لوحده، مش مخلوط مع جيش) ضد استراتيجيتين — يمسك جندي مكسور (بيكسب فوري في أقل من 60 ثانية) أو عديم الفائدة تماماً.
- **تماثل مواجهات المرآة**: نفس الاستراتيجية ضد نفسها لازم تدّي نتيجة متطابقة تماماً للطرفين. ⚠️ **ده مش بديهي** — أي تأثير جديد بيعدّي على اللاعب التاني (قدرة قائد، مهارة خاصة) لازم يتطبّق بترتيب مستقل عن "مين اللاعب A ومين B"، وإلا هتاخد أفضلية وهمية لطرف على التاني. راجع القسم اللي تحت — ده بالظبط الخلل اللي اكتشفناه أثناء بناء نظام القادة.

## قضية "هيمنة اقتصاد أولاً" — اتحلّت (تاريخ الحل، عشان أي حاجة مشابهة مستقبلاً)

جُرّبت 5 محاولات قبل الحل الفعلي: تكلفة/عائد المزرعة (مرتين)، سقف صارم لمزرعة واحدة، "الدفاع يتعزز مع الوقت" (غيّر التوقيت بس مش مين بيكسب) — **الحل اللي نفع**: خلي المزارع هدف هجوم حقيقي (`BUILDINGS.farm.goldPenalty`) بحيث تدميرها يسحب **ذهب مُدّخر بالفعل** مش بس يوقف الدخل المستقبلي. لوحدها إزالة الدخل المستقبلي ملهاش تأثير (اللاعب يكون خد الفايدة فعلاً قبل ما المزرعة تتدمر) — الدرس: عقاب مستقبلي بس مش كافي لتعويض سباق دخل تراكمي، لازم عقاب رجعي (retroactive) كمان.

## قضية "تماثل مواجهات المرآة" المكسور — اتحلّت (درس مهم لأي مهارة/قدرة جديدة)

لما ضفنا القادة، مواجهة "نفس الاستراتيجية ضد نفسها" (المفروض دايماً متماثلة) طلعت غير متماثلة. السبب: كنا بنطبّق كل تأثيرات لاعب واحد (هجوم + ترميم) بالكامل قبل ما ننتقل للتاني — فلاعب واحد كان بياخد فرصة يرمم الضرر اللي الخصم سببه لتوه في نفس اللحظة، والتاني (بالترتيب المعكوس) ملوش نفس الفرصة. **الحل**: نطبّق كل تأثيرات "الضرر" على الطرفين الأول، بعدين كل تأثيرات "الترميم" — مصنّفة حسب *نوع* التأثير مش حسب *مين اللاعب*. أي مهارة/قدرة جديدة تؤثر على اللاعب التاني لازم تتبع نفس المبدأ ده، والاختبار `sanity: a mirror matchup is symmetric` بيمسك أي رجوع للمشكلة.

## الأرقام المعتمدة حالياً (Snapshot)

راجع `src/content.js` للأرقام الفعلية دايماً (هو مصدر الحقيقة، مش هذا الملف) — لكن كملخص: مدة الجولة 360 ثانية، دفاع أساسي = برجين (700 HP) + قلعة (1200 HP) بتبدأ بـ35% وتتحصّن لـ100% على مدى 90 ثانية، مزرعة HP=60. القادة: شريط غضب 10 نقاط بمعدل امتلاء ثابت للجميع (`RAGE`)، 3 قادة كل واحد بمهارة غضب واحدة مُختبرة (الـ3 مهارات السلبية لكل قائد لسه مش متنفّذة). راجع `docs/PROGRESS.md` لتفاصيل رحلة الاختبار الكاملة.
